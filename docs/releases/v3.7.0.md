# Release Notes — v3.7.0

**Release Date:** August 23, 2026
**Branch:** `main`
**Type:** Minor version bump (2026 guardrail-gap subsystems + QA hardening)

---

## Highlights

🛡️ **Six new guardrail subsystems** — A complete `internal/guardrails` Go package implementing the 2026 guardrail-gap design specs under `docs/specs/guardrail-gaps-2026/`:
- **Prompt injection defense** (Spec 01) — 4-layer pipeline (pattern → perplexity → classifier → LLM self-check) with source-based trust policies.
- **Semantic content filtering** (Spec 02) — S1–S15 safety taxonomy (Llama Guard + coding-specific S14/S15), multi-backend (LlamaGuard via Ollama, OpenAI Moderation), policy engine with per-category/rule thresholds and overrides, result cache, fail-open/fail-closed.
- **Runtime sandbox isolation** (Spec 03) — L0/L1/L2 levels (direct / unshare namespaces / podman-docker rootless) with resource limits and network isolation.
- **Multi-agent safety policies** (Spec 04) — safety-chain with `scan_and_block`/`scan_and_warn`, constraint resolution, and FourLaws validators.
- **Indirect prompt injection / provenance** (Spec 05) — source-trust tracking, ROT13/obfuscation decoding, provenance cache.
- **Regulatory compliance mapping** (Spec 06) — maps guardrail features to frameworks (GDPR, SOC 2, ISO 27001, EU AI Act, etc.).

🔧 **Two new MCP tools** — `guardrail_classify_content` (classifies text against S1–S15 taxonomy; returns per-category scores and actions) and `guardrail_check_policy` (checks text against a named content policy; returns violations). Engine constructed in `cmd/server` when `OLLAMA_URL` is set (Llama Guard backend) with `OLLAMA_MODEL` overriding the default `llama-guard-3`.

🔒 **Security hardening — two full QA passes (48 findings resolved)** — Fail-closed everywhere:
- **Sandbox (2× P0)**: security denials at L2/L1 no longer cascade to host execution — fallback restricted to genuine setup errors and fails closed; `SandboxViolations` / `ErrSandboxViolation` now actually populated and returned.
- **Sandbox network**: `AllowedHosts` no longer silently uses `--network=host`; default is `--network=none` (fail-closed) with `NetworkMode` escape hatch.
- **Sandbox network egress (new)**: `AllowedHosts` at L2 now routes outbound traffic through a local CONNECT forward proxy on a `guardrail-egress` bridge network with `HTTP_PROXY`/`HTTPS_PROXY` injected; any setup failure falls back to `--network=none` (fail-closed).
- **Policy engine**: unknown `policy_id` fails closed (was `Compliant: true`).
- **Injection pipeline**: classifier-flagged input with low confidence reports `Safe: false`; unparseable Ollama output fails closed; `regexp2` patterns get a 2s match timeout; multi-agent validator errors fail closed; FourLaws scope check runs without context; destructive-command patterns resist flag-order and path obfuscation.
- **Content filter**: bounded result cache with max-size eviction, stoppable prune loop, cache invalidation on rule/backend changes, correct violence/graphic and sexual/minors score mapping.
- **Provenance**: glob `*` respects segment boundaries, cache keys include source/agent, `**` matches root files and requires a real middle segment, base64 decoding needs explicit marker, ROT13 detection strengthened, case-insensitive pattern matching.
- **Registry/MCP**: `EvaluateInput` honors explicit categories (no bash fallback), `guardrail_check_policy` / `guardrail_classify_content` docs match their registered schemas.

🧹 **House fixes** — Removed dead `internal/adapters` package (broken build since v3.2.0); fixed 5 pre-existing team-tool test failures (phase validation used wrong validator, ran after project load, read fixtures from repo root instead of package `.teams/` dir); removed `.gitignore` rule that silently ignored new `mcp-server/internal/mcp/*_test.go` files.

## What's New

### Six guardrail subsystems (`internal/guardrails`)

Each subsystem is backed by a design spec under `docs/specs/guardrail-gaps-2026/`:

| Spec | Subsystem | Key capabilities |
|------|-----------|------------------|
| 01 | Prompt injection defense | 4-layer pipeline (pattern, perplexity, classifier, LLM self-check); source-trust policies; trusted sources skip injection deep-scan only |
| 02 | Semantic content filter | S1–S15 taxonomy (Llama Guard + S14/S15 for code); LlamaGuard/Ollama and OpenAI Moderation backends; policy engine with thresholds/overrides; result cache; fail-open/fail-closed |
| 03 | Runtime sandbox | L0 (direct), L1 (unshare namespaces), L2 (podman-docker rootless); CPU/memory/pids limits; network isolation |
| 04 | Multi-agent safety | Safety chains (`scan_and_block`, `scan_and_warn`); constraint resolution; FourLaws validators |
| 05 | Indirect injection / provenance | Source-trust tracking; ROT13/base64/obfuscation decoding; provenance cache with glob matching |
| 06 | Regulatory compliance | Feature→framework mapping (GDPR, SOC 2, ISO 27001, EU AI Act, etc.) |

All new `.go` files enforce the 500-line file limit.

### New MCP tools

- **`guardrail_classify_content`** — Classifies input text against the S1–S15 taxonomy. Returns per-category scores, actions, and an aggregate decision. Registered with full schema and documentation.
- **`guardrail_check_policy`** — Evaluates input text against a named content policy. Returns violations with category, severity, and remediation guidance. Registered with full schema and documentation.

Engine wiring: `SetGuardrailsEngine` setter on `MCPServer` and `Engine.CheckPolicy` convenience method; engine constructed in `cmd/server` when `OLLAMA_URL` is set (Llama Guard backend) with `OLLAMA_MODEL` overriding the default `llama-guard-3`.

## Changed

### QA Review Pass 1 (12 findings)

Resolved across the new subsystems:
- Data races in concurrent cache access
- Taxonomy category mismatches between backends
- Fail-closed error paths not properly implemented
- Cache pointer sharing between goroutines
- Inert engine defaults (engine did nothing without explicit config)
- Sandbox violation detection no-ops behind passing tests
- Dead configuration fields never read
- Provenance cache deduplication issues

### QA Review Pass 2 (36 findings — 5 subsystem reviewers)

**Sandbox (2× P0):**
- Security denials at L2/L1 no longer cascade down to host execution — fallback is restricted to genuine setup errors and fails closed.
- `SandboxViolations` / `ErrSandboxViolation` are now actually populated and returned (previously a no-op behind passing tests).
- `AllowedHosts` no longer silently uses `--network=host`; default is `--network=none` (fail-closed) with a `NetworkMode` escape hatch.

**Policy engine:**
- Unknown `policy_id` fails closed (was `Compliant: true`).

**Injection pipeline:**
- Classifier-flagged input with low confidence reports `Safe: false`.
- Unparseable Ollama output fails closed.
- `regexp2` patterns get a 2s match timeout (ReDoS-safe).
- Multi-agent validator errors fail closed.
- FourLaws scope check runs without context.
- Destructive-command patterns resist flag-order and path obfuscation.

**Content filter:**
- Bounded result cache with max-size eviction.
- Stoppable prune loop.
- Cache invalidation on rule/backend changes.
- Correct violence/graphic and sexual/minors score mapping.

**Provenance:**
- Glob `*` respects segment boundaries.
- Cache keys include source/agent.
- `**` matches root files and requires a real middle segment.
- Base64 decoding needs an explicit marker.
- ROT13 detection strengthened.
- Case-insensitive pattern matching.

**Registry/MCP:**
- `EvaluateInput` honors explicit categories (no bash fallback).
- `guardrail_check_policy` / `guardrail_classify_content` docs match their registered schemas.

## Migrating from v3.6.0

### For users of the pi extension

No breaking changes to the pi extension. The new guardrail subsystems are opt-in via the MCP server configuration (`OLLAMA_URL` for Llama Guard backend).

### For MCP server operators

**New environment variables:**
- `OLLAMA_URL` — enables the Llama Guard backend for content classification (e.g., `http://localhost:11434`).
- `OLLAMA_MODEL` — overrides the default `llama-guard-3` model.

**New tools available:**
- `guardrail_classify_content` — classify text against S1–S15 taxonomy.
- `guardrail_check_policy` — check text against a named content policy.

**Fail-closed behavior changes:**
- Unknown `policy_id` now returns a violation instead of `Compliant: true`.
- Sandbox network defaults to `--network=none`; existing `AllowedHosts` configurations will need explicit `NetworkMode` if host networking was intended.
- Classifier errors and unparseable backend output now fail closed.

Review the design specs under `docs/specs/guardrail-gaps-2026/` for full subsystem semantics before enabling.

## Known Follow-ups (non-blocking)

These were identified during review and tracked as future work, not blockers for this release:

- **Sandbox L2 podman integration test** — requires podman in CI; currently validated at L0/L1 only.
- **Content filter cache metrics** — no Prometheus exporter for cache hit/miss/eviction rates.
- **Provenance cache TTL** — currently unbounded; eviction policy needed for long-running servers.
- **Multi-agent FourLaws context propagation** — scope check runs without context; future spec may add context-aware constraint resolution.
- **Regulatory mapping completeness** — current mapping covers major frameworks but not all regional variants (e.g., CCPA, LGPD).
- **OpenAI Moderation backend retry/backoff** — currently single attempt; exponential backoff would improve resilience.
