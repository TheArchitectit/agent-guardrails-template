# Release Notes — v3.8.6

**Release Date:** November 13, 2026
**Type:** Patch (CI routing and the gate that enforces it)

## What shipped

- **All CI runs on the repo-scoped UCS03 runner.** Every job in every
  workflow now targets `[self-hosted, Linux, X64, guardrails-ucs03]`. The
  GitHub-hosted rows are gone; there is no hosted fallback left in this
  repository.
- **Same-repository PRs run on the fleet behind a fork guard.** Every job of a
  workflow that declares `pull_request` carries

  ```yaml
  if: github.event_name != 'pull_request' || github.event.pull_request.head.repo.full_name == github.repository
  ```

  GitHub evaluates a job-level `if:` **before** it assigns a runner, so a fork
  PR's jobs are skipped rather than dispatched. One unguarded job would be
  enough to put contributor code on the private host, which is why the rule is
  per job. `pull_request_target` is refused outright: it runs a base-repository
  workflow against a PR-controlled checkout with a writable token.

- **Spec 19 R19-13 revised.** The requirement previously required PRs and
  forks to stay on GitHub-hosted runners. It now states the routing above and
  keeps every isolation clause: clean checkout, no cross-repository
  workspace/artifact/cache/credential reuse, least-privilege token, bounded
  concurrency, post-job cleanup, and a recorded attestation.

- **`scripts/check_runner_isolation.py` rewritten.** It no longer requires PR
  workflows to be hosted or the fleet label to live in one file. It enforces
  the new posture — and two rules it did not have before: the fork guard on
  every job of every `pull_request` workflow, and no `actions/cache`,
  checkout `path:` or foreign `repository:` in **any** fleet job, not only the
  trusted one. Non-vacuity now covers three counts (workflows, PR workflows,
  fleet jobs), so a green run cannot come from scanning nothing.

## Validation

- `python scripts/check_runner_isolation.py --repo .` →
  `R19-13 OK: 8 workflow(s), 49 job(s) on guardrails-ucs03, 5 pull_request
  workflow(s) with a fork guard on every job`.
- `python scripts/test_check_runner_isolation.py` → 32 passed. New red-on-drift
  cases: a missing guard, an inverted (`&&`) guard, one unguarded job among
  guarded ones, `pull_request_target`, a hosted label, an expression
  `runs-on:`, an unknown label, and shared-cache/foreign-checkout in a
  non-trusted fleet workflow.
- The regression-guard suite run verbatim: action pins, resource claims, image
  pins, secret argv/inventory, charset, Go modules, Python tests, mandatory
  rows, tool count, policy-pack lock, `regression_check.py --all` and
  `check_doc_length.py` — all exit 0 on this tree.
- The YAML parses and every job of every `pull_request` workflow was checked
  mechanically (49 jobs, 5 PR workflows) before the tag was created.

`Release Coverage` requires HEAD itself to be the annotated `v3.8.6` tag
named by `VERSION`, with a `## [3.8.6]` changelog heading — which is why the
version artifacts are updated in the tagged commit, not in a later one.

## Deliberate boundaries

No product code, policy pack, or spec behavior changes outside Spec 19's
runner clause. The private fleet remains one repo-scoped runner; spares are the
autoscaler's job, and a burst of 49 jobs will queue on the base runner until a
guardrails lane is registered.

## Version ancestry

This release sits directly on `v3.8.5`. `VERSION`, `CHANGELOG.md`, the release
notes, the releases index, and the README are updated in the tagged commit
itself.
