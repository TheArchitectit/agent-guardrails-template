# Release Notes — v3.8.7

**Release Date:** November 13, 2026
**Type:** Patch (two red CI jobs found on the first fleet-routed run)

## What shipped

- **`Secret Validation` stops failing after a clean scan.** `gitleaks-action`
  uploads `results.sarif` with `process.env.HOME` as the artifact root and
  `results.sarif` as a relative path. On GitHub-hosted runners `HOME`
  (`/home/runner`) is an ancestor of the workspace; on the UCS03 runner it is
  not (`/home/runner` vs `/_work/agent-guardrails-template/agent-guardrails-template`),
  so the artifact client throws after the scan finishes:

  ```text
  Error: The rootDirectory: /home/runner is not a parent directory of the file:
  /_work/agent-guardrails-template/agent-guardrails-template/results.sarif
  ```

  The scan itself was clean — `no leaks found`, gitleaks exit 0 — and the job
  still went red. The step now sets `GITLEAKS_ENABLE_UPLOAD_ARTIFACT: "false"`,
  which disables exactly that upload block; the scan and its
  `--exit-code=2` gate are untouched, and no workflow in this repository
  ingests the SARIF (there is no code-scanning upload step).

- **`Release Published` can publish from the fleet.** The publisher called
  `gh release create` / `gh release view`. The UCS03 runner image carries the
  Actions runner and the gate toolchain but no `gh`, so the tag-triggered run
  for `v3.8.6` wrote its notes and then exited 127:

  ```text
  release notes: 33 line(s) from ## [3.8.6]
  /_work/_temp/…sh: line 50: gh: command not found
  ```

  `v3.8.6` is therefore tagged on `main` but was never published as a GitHub
  Release. Publishing now goes through the REST API with `python3`/`urllib`,
  keeping the same contract: an existing release is success and its URL is
  printed; otherwise the workflow creates it and requires a read-back before
  printing the URL, so a "published" line always names a release the API
  serves. A concurrent `already_exists` response is treated as success.

## Validation

- Both Python blocks in `release.yml` compile under `python3 -m compileall`
  semantics; the publish block was exercised live against the existing
  `v3.8.5` release and printed its URL without attempting a create.
- `python scripts/check_runner_isolation.py --repo .` → `R19-13 OK: 8
  workflow(s), 49 job(s) on guardrails-ucs03, 5 pull_request workflow(s) with
  a fork guard on every job …` on this tree.
- The regression-guard suite (action pins, resource claims, image pins, secret
  argv/inventory, charset, Go modules, Python tests, mandatory rows, tool
  count, policy-pack lock, `regression_check.py --all`, `check_doc_length.py`)
  runs verbatim on this tree before the tag.
- Evidence for the two fixed failures: run `43333849222` (Secret Validation)
  and run `43333853983` (Release Published) at `d3ec374`.

## Deliberate boundaries

- The `v3.8.6` tag is not moved, deleted or re-created. It stays where it was
  published; this release is the fix and the first tag whose publisher can
  run on the fleet.
- The runner image itself is unchanged. Installing `gh` into it is a
  fleet-wide image change (the image is shared by the guardrails lane) and is
  not needed by any other workflow in this repository.

## Version ancestry

notes, the releases index and the README are updated in the tagged commit
