# Release Notes — v3.8.13

**Release Date:** November 27, 2026  
**Type:** CI portability and local validation

## What changed

- **Workflow runner selection is configurable.** Jobs use the repository
  variable `CI_RUNNER_LABELS` as a JSON array of runner labels, defaulting to
  `["ubuntu-latest"]` when unset. The repository can select the UCS03 lab
  with `["self-hosted","Linux","X64","guardrails-ucs03"]`. Per-job fork
  guards remain required so fork pull requests are skipped before a private
  runner is assigned. The static isolation checker accepts only the reviewed
  selector expression or an explicit runner label list containing the UCS03
  label.
- **A local CI command is available.** `scripts/run_local_ci.sh` reads the
  Python and Go test inventories, runs their declared suites and Go builds,
  checks positive test floors, and runs selected deterministic regression
  gates and the approved AIGGP charset check. It requires preinstalled tools
  and an already prepared, clean `.devgate` checkout at the pinned revision.
- **Local Go race commands enable CGO.** The local runner sets `CGO_ENABLED=1`
  for Go tests, builds, and test discovery; a C compiler is required.

## Validation scope

The local command validates the declared inventories and selected regression
gates. It does not reproduce every GitHub Actions job, event-bound PR or push
check, upload GitHub artifacts, or attest the UCS03 runner host. The
Docker/Podman context integration test remains opt-in and needs an available
engine daemon. The runner-selector self-test exercises the static policy; it
does not schedule a GitHub-hosted or self-hosted job.

These notes cover the CI portability candidate through commit `5a5bb457`; they
do not claim a completed hosted workflow run or a full local run of the entire
CI matrix. The v3.8.13 annotated tag and GitHub Release are pending
release-owner publication.
