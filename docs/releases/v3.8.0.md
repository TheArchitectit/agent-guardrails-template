# Release Notes — v3.8.0

**Release Date:** November 5, 2026
**Type:** Minor (guardrail capabilities, evidence API, sandbox isolation, release automation)

## What shipped

- **Evidence verification:** `POST /api/evidence/verify` is routed through the web
  server and authorized through the existing policy boundary. Trust-store and
  revocation-snapshot inputs are validated. Cross-product evidence is bounded
  context for a decision; it never authorizes an OpenAgentPlatform effect.
- **Sandbox configuration:** declared secret names are scrubbed from direct and
  namespace execution environments. Rootless L2 can receive explicitly selected
  environment variables, and the capability matrix now includes the tested
  state-persistence behavior. Callers still choose and configure isolation.
- **Guardrail subsystems:** current main contains injection detection,
  streaming content classification, L0–L2 sandbox execution, multi-agent
  conflict handling, provenance chains/caches/ledgers, and compliance mapping.
  Optional classifier backends and server integration determine what is live.
- **Release automation:** an annotated version tag publishes a GitHub Release
  after checking its commit, `VERSION`, and dated changelog section. Release
  Coverage checks that product commits on `main` match their declared release.
- **Documentation:** the root and MCP-server READMEs follow the release version
  and explicitly distinguish active integration, optional backends, library
  helpers, and proposed controls.

## Deliberate boundaries

This is not a claim that every specification or runtime integration is complete:

- Injection L4 LLM self-check has no implementation. Enabling it refuses engine
  construction rather than silently skipping the layer.
- The Redis provenance cache and system-prompt augmentation helper have no
  production caller; the engine selects the in-memory cache.
- The OAP checker is implemented and tested as a library only. It has no MCP
  tool or HTTP route in this release.
- Spec 12 remains proposed beyond the production/public exposure narrowing that
  is implemented here.

## Validation

The release tree is validated with Go build and full package tests, the
repository's Python documentation/tool-policy gates, action-pin checks, and the
trusted workflow checks after publication. Skipped tests and runtime services
are not promoted to production behavior.
