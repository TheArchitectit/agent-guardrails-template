# Release Notes — v3.4.0

**Release Date:** August 15, 2026
**Branch:** `main`

---

## Highlights

📚 **Complete documentation redo** — Every markdown file reorganized into a clean taxonomy, renamed to consistent `kebab-case`, and trimmed under the 500-line limit. Duplicates merged, stale point-in-time docs archived, and the navigation system rebuilt from scratch. Old doc links break; see the migration note below.

🔌 **pi-extension restored** — The TypeScript guardrails extension for the pi coding agent is back on `main`. It had been living on a feature branch since v0.2.0 and never merged. Brought in cleanly without the conflicts a full branch merge would have caused.

🗂 **Game and vision content split into private repos** — 3D game-development skills, game-design docs, and the vision pipeline docs moved to where they belong: a new private `agent-guardrails-game-design` repo and `radredeye` (which will own vision capture and review long-term). The public repo is now purely a guardrails framework.

🧹 **Dead code removed** — `game_build.go` and the game validator, which compiled but were never wired up as MCP tools and had no callers, are gone.

🗺 **HEADER_MAP dropped** — The 1033-line line-number reference map broke on every edit. Replaced with a lean `index-map.md` plus per-directory `INDEX.md` files that don't go stale.

## What's New

### Documentation restructure

The docs were a mess — 164 files with three different naming schemes, nine pairs of overlapping or duplicate docs, point-in-time reports reading as current, and a navigation system that broke every time anyone moved a section. This release fixes all of it:

- **New taxonomy** — `getting-started/`, `architecture/`, `integrations/`, `teams/`, `mcp-server/`, `rules/`, plus the existing domain directories and a new `archive/`.
- **Consistent naming** — everything is `lowercase-kebab-case.md` now (README, CHANGELOG, CONTRIBUTING, CLAUDE excepted).
- **Duplicates merged** — OpenCode (two files, one a typo), Python migration (two takes on the same topic), Contributing (root + docs), and the rules meta-docs.
- **Stale docs archived** — 21 historical docs (the 2093-line "planning" server plan, an April audit, gap analyses, all sprint records, a superseded architecture map) moved to `docs/archive/` with a README flagging them as not-current.
- **Oversized files split** — 18 files were over the 500-line limit. The worst offenders (team-tools at 1199, API at 962, prompting-guide at 984, troubleshooting at 767) decomposed into focused sub-documents. All but two are now under 500.
- **Lean navigation** — `index-map.md` rewritten as a keyword→file map, `toc.md` trimmed to a flat listing, 24 per-directory `INDEX.md` files added, and `HEADER_MAP.md` deleted.

### pi-extension

The `@thearchitectit/pi-guardrails` extension — a standalone Four Laws enforcer for the pi coding agent, with an optional MCP bridge to the Go server — is on `main` again. 63 files: MCP bridge, injection detector, sandbox runner, policy loader, output validator, 10 skills.

### Content relocated to private repos

- **`agent-guardrails-game-design`** (new private repo) — game design docs, 3D development guardrails, Hermes 2026 / AI_DEV_2026 guides, and the 3d-game-dev skill copies.
- **`radredeye`** (existing private repo) — vision pipeline docs and config. radredeye will do both vision capture and screenshot review long-term, superseding this repo's game-specific Go prototype.

### Code cleanup

- Deleted `game_build.go`, `game_validator.go`, `game_validator_test.go` — dead code (compiled, never registered, no callers).
- The vision Go pipeline (13 files) stays for now, gated behind `VISION_ENABLED`, until radredeye reaches feature parity.

## Migrating from v3.3.x

This is a documentation restructure — **no code or API changes**. The MCP server, tools, and endpoints are identical to v3.3.0.

**If you linked to specific doc files**, those paths changed. Old filenames like `docs/AGENT_GUARDRAILS.md` are now `docs/getting-started/agent-guardrails.md`. Start at the [README](../../README.md) or [index-map.md](../../index-map.md) to find the new locations.

**If you clone for the docs**, nothing else changes — the server build, deployment, and tool set are the same.
