# Release Notes — v3.8.3

**Release Date:** November 9, 2026
**Type:** Patch (documentation and CI permissions)

## What shipped

- **A submodule embedding & consumer wiring guide.** New
  `docs/getting-started/submodule-and-consumer-wiring.md` documents the second
  way to consume this repository: instead of copying advisory files into a
  target repo (copy-in mode, still described in
  [how-to-apply](../getting-started/how-to-apply.md)), embed the repository
  itself as a git submodule checkout so the framework's own gates, CI, and
  self-update path remain available under version control alongside the
  consumer. The guide gives the consumption-mode comparison, the
  `git submodule add` procedure, the coercion and scope lesson, coexistence
  with a second framework gate submodule (DevGate), living with the pin, and a
  wiring verification checklist.
- **Entry points updated.** `README.md` links the guide from the Copilot
  integration section, `how-to-apply.md` opens with an "if you embed instead of
  copy" pointer, and `index-map.md` / `toc.md` index it under the
  submodule / embed / vendored / consume keywords.
- **`regression-guard.yml` can comment on pull requests again.** Its
  `Comment PR` step posts the Regression Guard summary with the job token.
  Without an explicit `permissions:` block that token is read-only outside main
  pushes, so every `pull_request` run failed with
  `Resource not accessible by integration` (403) after all regression gates
  inside the job had passed. The workflow now requests `contents: read`,
  `issues: write` and `pull-requests: write`; nothing else in the job gains
  scope.

## Validation

`openspec validate --all --strict` — this release touches documentation and
one workflow's permissions block, neither of which changes a spec. The pinned
`.devgate` deploy pipeline runs `regression_check.py --all --pre-commit` and
`guardrails-scan.mjs` over this tree before the tag is created.
`Release Coverage` requires HEAD itself to be the annotated `v3.8.3` tag named
by `VERSION`, with a `## [3.8.3]` changelog heading — which is why the version
artifacts are updated in the tagged commit, not in a later one.

## Deliberate boundaries

No product code, guardrail rule, policy pack, or spec behavior changes. The
copy-in path is untouched; the new document describes an embedding contract
that the repository already supports through its own CI. The PR-comment
permission change repairs the reporter, not the gates — the gates were already
running and passing when the comment step failed.

## Version ancestry

This release sits directly on `v3.8.2`. `VERSION` and `CHANGELOG.md` are
updated in the tagged commit itself, so the v3.8.2 defect (a tag on a commit
that still said 3.8.1) is not repeated.
