# Release Notes — v3.8.4

**Release Date:** November 12, 2026
**Type:** Patch (guardrail rule and the documentation it contradicted)

## What shipped

- **`PREVENT-SUB-001` blocks tooling submodules from being committed into a
  consumer repo.** A change to `.gitmodules` naming
  `agent-guardrails-template` (or `DevGate-Agentic-Framework`) is a `critical`
  pattern violation in the prevention-rule set. The tooling checkout is
  local-only: run the gates from it on disk and push only the consumer's own
  code fixes.
- **The embedding guide now describes the contract the rule enforces.**
  `docs/getting-started/submodule-and-consumer-wiring.md` previously taught
  `git submodule add … .agent-guardrails` and
  `git commit -m "chore: embed agent-guardrails-template …"` — exactly what
  the new rule rejects — and v3.8.3 shipped that as the embed mode's contract.
  The guide now records the committed embed as **blocked**, keeps copy-in as
  the supported path, and describes the local, untracked checkout
  (`git clone … .agent-guardrails` + gitignore) as the way to keep the
  framework's gates available without committing them. The coexistence table,
  the "living with" rules, and the verification checklist follow the same
  contract; `how-to-apply.md`'s pointer and `README.md`'s version section were
  updated with it.

## Validation

`openspec validate --all --strict` — this release changes one prevention rule
and the documentation around it, neither of which changes a spec. The
regression gate and the guardrails scan run over this tree before the tag is
created. `Release Coverage` requires HEAD itself to be the annotated `v3.8.4`
tag named by `VERSION`, with a `## [3.8.4]` changelog heading — which is why
the version artifacts are updated in the tagged commit, not in a later one.

## Deliberate boundaries

No product code, policy pack, or spec behavior changes. The rule is data in
`.guardrails/prevention-rules/pattern-rules.json`; the rest of this slice is
documentation brought in line with it. Copy-in mode is untouched.

One consequence is recorded rather than resolved here: a consumer that already
committed a `.gitmodules` entry per the v3.8.3 guide is now sitting on a
`critical` violation the moment that file changes. Removing the registration
and switching to a local checkout is the remediation the rule's suggestion
names; whether a grandfathering exception should exist is an owner decision.

## Version ancestry

This release sits directly on `v3.8.3`. `VERSION`, `CHANGELOG.md`, the release
notes, the releases index, and the README are updated in the tagged commit
itself.
