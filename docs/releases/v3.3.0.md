# Release Notes — v3.3.0

**Release Date:** August 15, 2026
**Branch:** `main`

---

## Highlights

🚀 **Stateless StreamableHTTP Transport** — The MCP server now speaks the modern MCP HTTP transport. One `POST /mcp` endpoint, no session IDs, no persistent connections. Clients get simpler setup; the server scales horizontally without sticky sessions.

🛠 **The build actually works now** — v3.2.0 shipped with an `internal/mcp` package that didn't compile. We ported it to mcp-go v0.58.0 and fixed the type mismatches. `go build ./cmd/server/` succeeds cleanly.

🗃 **Fresh installs finally work end-to-end** — All 18 database migrations repaired and renumbered into a clean sequence. A fresh database now gets all 22 tables with zero errors.

🐳 **Containers start on the first try** — PostgreSQL and Redis no longer crash-loop on a fresh deploy. Capability sets fixed, Redis config passed via CLI flags, `BIND_ADDR` added to control which interface ports bind to.

🔐 **JWT secret validation fixed** — The old check rejected perfectly good `openssl rand -hex` secrets. The new one uses Shannon entropy and accepts any genuinely random secret.

🧹 **Major repo cleanup** — Removed ~53MB of committed binaries and tarballs, dead test data, and duplicated docs. Game-design content moved to a private companion repo.

## What's New

### Stateless StreamableHTTP Transport

The biggest change in this release. The old SSE transport required a two-step
connection dance — open a `GET /sse` stream, then POST messages with a session
ID. The new transport collapses that into a single endpoint:

```bash
curl -X POST http://your-server:8080/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2024-11-05",
      "capabilities": {},
      "clientInfo": { "name": "test", "version": "1.0" }
    }
  }'
```

Every request is independent. There's nothing to keep alive and nothing to
time out, which makes the server trivial to run behind a load balancer.

Client configs need a one-line change — see the migration section below.

### Configurable Bind Address

By default the stack binds to `127.0.0.1` — reachable only from the host
itself. Set `BIND_ADDR` in your `.env` to bind to a different interface (for
example, a Tailscale IP if you want the server reachable on your tailnet).

## What's Fixed

### Build & Toolchain

- **Go 1.25+ required.** The Dockerfile builder was pinned to Go 1.23 and CI
  to Go 1.21 — both too old to build the module. Updated everywhere.
- **`internal/mcp` ported to mcp-go v0.58.0** — the package was written
  against an API that never existed in any released version.

### Database Migrations

Fresh installs were broken by a pile of migration bugs, now all repaired:

- `failure_registry` and `audit_log` were declared as partitioned tables with
  primary keys that omitted the partition column — invalid in PostgreSQL, so
  the tables never got created. Now plain tables.
- Removed a call to a partition-management function that doesn't exist.
- Fixed a trailing-comma syntax error and a `VARCHAR`→`UUID` foreign key.
- Removed foreign keys pointing at tables that don't exist in this schema.
- Renumbered migrations into a clean 001–018 sequence (duplicate numbers had
  broken golang-migrate's ordering).

### Containers

- **PostgreSQL** no longer needs `no-new-privileges` removed entirely — it
  runs with the minimal capability set its entrypoint requires.
- **Redis** configuration moved to CLI flags (the config directory the old
  setup referenced doesn't exist in `redis:7-alpine`).
- Dropped the deprecated `version:` key from compose files.

### Config Validation

- **JWT secret check rewritten** — the old check counted set bits per byte,
  which measures bit density, not randomness. Random hex secrets randomly
  failed it. The new check uses Shannon entropy over byte frequencies.

## Migrating from v3.2.x

1. **Update your MCP client config** to point at the new endpoint:

   ```jsonc
   {
     "mcpServers": {
       "guardrails": {
         "type": "remote",
         "url": "http://your-server:8080/mcp"
       }
     }
   }
   ```

   The old SSE URL (`/mcp/v1/sse`) returns a 404 in v3.3.0.

2. **Regenerate API keys if they're hex-only.** The key validator requires a
   mix of upper, lower, and digits — use `openssl rand -base64`, not `-hex`.

3. **Upgrade Go to 1.25+** if building from source.

4. **Fresh databases:** migrations apply cleanly. If you have a database with
   partially-applied old migrations, drop and recreate it (no production data
   lives in the tables that were previously broken).

5. **Ports default to localhost.** Set `BIND_ADDR` only if you need the server
   reachable off-box.
