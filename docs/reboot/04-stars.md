# Star growth roadmap: 100 / 1,000 / 10,000 / 100,000
Prepared Oct 1, 2026. Assumption: Roger's "100, 1000, 10000, 10000" means 100, 1,000, 10,000 and 100,000 (tell us if not).

## Baseline
agent-guardrails-template showed 76 stars, 2 forks, 0 open issues on its GitHub page on Oct 1, 2026 (https://github.com/TheArchitectit/agent-guardrails-template). The default branch is currently a retirement README, so the first visitor experience is poor and fixing that comes first.

## Honest framing
Stars follow usefulness, trust and visibility, in that order. Nobody can promise a date for any milestone. 100,000 is rare. Treat the thresholds as direction, and measure the leading indicators below. Earned tactics only: no bought stars, no star-exchange groups, no sock accounts, no gift-for-star schemes. These violate GitHub's rules and would wreck a safety project's credibility.

## Leading indicators (track weekly)
Unique repo visitors, README-to-install conversion, installs completed, issues from non-team users, PRs from outside contributors, time-to-first-response, return visitors, mentions by others.

## Stage 0 to 100 stars (Milestone M0, 76 to 100)
Goal: make the repo worth starring.
- Restore a real default branch via the review branch plan (needs Roger's approval before any write).
- README: what it does, honesty table, 60-second demo, install steps that work.
- Publish the near-loss story (after approval) with the repo link.
- Ask the 76 existing stargazers' community only through normal posts; no DMs en masse.
- Topics, description, social preview image, license visible, SECURITY.md.
Evidence of done: new visitor can install and see a verdict in 5 minutes on a clean machine.

## 100 to 1,000 (M1 to M2)
Goal: be genuinely useful in one place, Copilot in VS Code.
- Ship working MCP setup and extension (F031-F033), a status panel that tells the truth.
- Submit to relevant directories only when criteria are met: MCP Registry (preview; needs a published package and verified name, see https://modelcontextprotocol.io/registry/quickstart), VS Code marketplace.
- Launch posts on communities where the topic fits (dev.to, relevant subreddits, Hacker News Show HN) once the demo works; follow each community's self-promotion rules; one launch per channel.
- Weekly build-in-public notes; monthly safety notes including failures.
- 15 well-labeled good-first-issues; reply within 48 hours.
- Outreach: email maintainers of related projects with a useful, specific note (integration or comparison), not a request for stars.
- Talks: submit to 3 meetups or lightning-talk slots with the story.

## 1,000 to 10,000 (M3 to M4)
Goal: be the reference for honest agent-safety tooling.
- Second and third hosts (Claude Code, Cursor), host compatibility matrix, GitHub Action for PR evidence reports.
- Publish a threat model and a labeled benchmark with real failure cases. Honest numbers get shared.
- Write 4 deep technical posts (why advisory is not enforcement, permit tokens, hash-chained evidence, incident-to-rule).
- Conference talks and a podcast circuit around the near-loss story.
- Contributor program: recognition, maintainers ladder, release rotation.
- Integrate with other tools by opening PRs to their docs where we add real value.
- Third-party review of the check logic, results published.

## 10,000 to 100,000 (M5 to M6)
Goal: ecosystem standard.
- Policy pack registry, benchmark suite, shared evidence format that other tools adopt.
- Vendor-neutral spec for operation permits, proposed to relevant working groups.
- Education: workshop kit, course material, translations.
- Partnerships with host vendors only on technical merit.
- Sustainable maintenance: funding model, governance doc, multiple maintainers.

## Anti-patterns (do not do)
Buying stars or followers; asking for stars in exchange for anything; mass-tagging strangers; posting identical self-promo across subreddits; overclaiming protection; hiding failures; publishing before README install works.

## Weekly operating rhythm
Mon: triage issues. Wed: ship something small and note it. Fri: publish a short note. Monthly: review indicators, drop tactics that don't move conversion.

Approve restoring a working default branch on a review branch; approve public story; choose domain/hosting; approve any paid tool.
