### Test/verification interpretation

This matrix lists focused test symbols found in the source. It does not claim those tests were run during this review. Tests demonstrate their specific unit/integration path. Closure status currently conflates: configuration validity, local library behavior, end-to-end consumer wiring, real host/runtime behavior, signed evidence, and release policy enforcement. Those are separate proof levels. In particular, the sandbox's safe future runtime validation should use benign probes that confirm an explicitly permitted write/read/network request succeeds and an explicitly denied request is rejected; it need not create escape payloads. The current static conformance helper does not make that runtime observation.

### Additional requirement-specific gap: semantic redaction is not implemented in the Go filter

The canonical indexed semantic specs also state `redact` as an available mediation action and require removal of the offending span plus a span digest in evidence (`semantic-filtering-categories-and-actions/spec.md:13`; `semantic-filtering-evidence-and-conformance/spec.md:13-19`). Yet `mcp-server/internal/guardrails/content_filter_config.go` defines only `ActionBlock`, `ActionWarn`, `ActionAllow`, `ActionScanAndWarn`, and `ActionScanAndBlock`; `validContentAction` accepts only block/warn/allow. A repository-wide search found no Go `ActionRedact` or span-removal implementation in the filter. The Pi output validator has a distinct optional local `autoRedact` feature, but its documented handler only warns/logs because `tool_result` is side-effect only, and it does not attach the required evidence span digest. This row should not remain EXERCISED; link to RUN-05 for the missing redaction action and RUN-04 for span-digest evidence.
