# Authorize every enabled optional MCP and REST path

## Context

The optional Vision dispatch runs ahead of the common MCP authorization and decision audit. Vision REST has its own registration group. An adopter needs a verified decision boundary for every enabled path.

## Decisions

Enumerate registered tools and REST verbs before choosing a shared wrapper. Reuse server-resolved principals and the existing action classification. The supported deployment profile declares effective optional surfaces. Audit carries bounded request identity, decision, policy and operation.

## Risk and verification

A path can authorize after handler initialization or write auxiliary data before denial. Verify invocation and side-effect counters at the actual registered transport. Exercise both classes of operations with synthetic data.

## Rollout

Review the scenario matrix, exercise it with an isolated configuration, and record exact source and artifact identities before enabling the supported profile or recording acceptance.
